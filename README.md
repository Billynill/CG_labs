# 🌋 Vulkan Starter App

## Getting started

You need C++ compiler, Vulkan SDK and CMake installed before you can build this project.

This project uses C++20 standard and thus requires either of those compilers:
- GCC 10.X
- Clang 10
- Microsoft Visual Studio 2019

This is officially tested on *Windows* and *GNU/Linux platforms*, no *macOS* support yet.
If you have a working macOS solution of this code, consider submitting a PR so others
can build this example code without a hassle!

<ins>**1. Downloading the repository**</ins>

Start by cloning the repository with `git clone --depth 1 https://github.com/vladeemerr/vulkan-starter-app`

This repository does not contain any submodules, it utilizes CMake's `FetchContent` feature instead.

<ins>**2. Configuring the project**</ins>

Run either one of the CMake lines to download dependencies and configure the project:

```bash
cmake --preset debug       # for GNU/Linux (GCC/Clang)
cmake --preset msvc-debug  # for Windows (Visual Studio 2019)
cmake --preset mingw-debug # for Windows (MinGW)
```

If you wish to build in `release` mode, change `debug` to `release`.

If changes are made (added/removed files), or if you want to regenerate project files, rerun the command above.

<ins>**3. Building**</ins>

To build the project, use the line below. You are most likely using `debug` preset, so
the directory that will eventually contain your build files is named `build-debug`.

Likewise for `release` that directory will be named `build-release`

Run one those commands, depending on which preset you chose:

```bash
cmake --build build-debug --parallel # for debug
cmake --build build-release --parallel # for release
```

### Running

`build-*` directory will contain the executable in one of the subdirectories after successful build.

For `msvc-{debug|release}` builds output subdirectory is set to `Debug` or `Release` respectively.
For other configurations output subdirectory is set to `vulkan-starter-app`.

**Make sure your working directory is set to the project root!**
Project root is where this README file resides. Otherwise, the
code responsible for loading shaders or other resources from files will fail,
because relative paths are used.

### Compiling shaders

`CMakeLists.txt` has a build recipe for compiling shader files
along with an application. Look for a comment in this file to see
how to compile your shaders.

## Laboratory work 2: camera and lighting

Scene: floor, back wall and two cubes (normals are generated procedurally in `source/cube.hpp`).

- **Camera**: position, yaw/pitch, FOV in the UI; `RMB + mouse` to look around, `WASD`/`QE` to move, `Shift` to speed up.
- **Lighting**: Blinn-Phong in `shaders/lit.frag` with ambient light, one directional light,
  an array of point lights and an array of spot lights (inverse-square falloff, soft edges between the inner and outer angles).
- **Descriptor sets**: set 0 holds the scene uniform buffer plus two storage buffers with lights
  (unsized arrays in the shader; buffers grow automatically when lights are added), set 1 holds the model matrix and material.
- **UI**: add/remove point and spot lights, edit every parameter, edit materials (albedo, specular color, shininess).
- **Light visualization**: unlit cubes in the light color and white wireframe cones for spot lights (`shaders/unlit.*`), toggled in the UI.
- Extras: orbiting point lights, a spinning cube, and a spot light that can be attached to the camera as a flashlight.

## Laboratory work 3: texturing

Builds on laboratory work 2 (camera, Blinn-Phong lighting, light visualization).

- **Vertices** have position, normal and UV; UVs are generated procedurally by projecting each vertex onto the face's right/up axes (`source/cube.hpp`).
- **Textures** are PNG files in `textures/`, loaded with `stb_image` (`source/texture.cpp`), copied to VRAM via a staging buffer, with mipmaps generated by `vkCmdBlitImage`.
  Regenerate them with `python3 tools/generate_textures.py` (needs `numpy` and `Pillow`; emissive maps are made from Perlin noise).
- **Materials**: each texture set (albedo + specular + emissive) has its own descriptor set; pick one per object in the UI.
  Missing specular/emissive maps are replaced by a 1x1 black texture, so no highlight and no glow.
- **One dynamic uniform buffer** stores `ModelData` for every object; the per-object offset is passed to `vkCmdBindDescriptorSets`.
- **Animated sampling** (the "Magic cube"): three time-dependent samples of the same texture (scroll, rotation + zoom, waves) mixed and color-modulated; enabled by a flag in push constants.
- **Vertex and index buffers** live in VRAM and are uploaded with a staging buffer and `vkCmdCopyBuffer`.
